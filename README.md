# Avito BootCamp September 2026 NLP

Для каждого запроса отбираем 50 объявлений-кандидатов. Метрика — recall@50: доля выбранных пользователем объявлений, попавших в кандидаты.

**Решение:** BM25 с лемматизацией + дообученная `multilingual-e5-base`, у обоих бонусы за локацию и вид услуги, списки объединяются через Reciprocal Rank Fusion.

| | валидация | Stepik |
|---|---|---|
| итоговое решение (`config.yaml`) | **0.887** | _—_ |
| без дообучения (`config_no_finetune.yaml`) | 0.840 | _—_ |

## Запуск

```bash
pip install -r requirements.txt && pip install -e .
# train.parquet, benchmark_queries.parquet, benchmark_items.parquet -> data/raw/

python scripts/run_all.py           # все этапы по порядку, остановка при ошибке
```

Флаги `run_all.py`: `--no-eval` — без оценки на валидации, `--config config_no_finetune.yaml` — без дообучения. Уже обученная модель повторно не обучается.

По этапам:

```bash
python scripts/preprocess.py        # чистка текстов              -> data/processed/
python scripts/make_validation.py   # валидация под benchmark     -> data/processed/val_*, train_part
python scripts/finetune.py          # дообучение (GPU, ~30 мин)   -> artifacts/models/e5-base-ft/
python scripts/evaluate.py          # recall на валидации         -> artifacts/metrics.json
python scripts/predict.py           # ответ                       -> answer.csv
```

- **Только ответ, модель уже есть** (скопирована в `artifacts/models/e5-base-ft/`): `run_all.py --no-eval` или `preprocess` -> `predict`.
- **Без дообучения:** `run_all.py --config config_no_finetune.yaml --no-eval` или `preprocess` -> `predict --config config_no_finetune.yaml`.

Эмбеддинги корпуса кешируются в `artifacts/embeddings/<key>/`: первое кодирование ~6 мин на GPU, на CPU порядка часа. При смене модели меняйте `key` в конфиге. Нужно ~16 ГБ RAM. На видеокартах с памятью меньше 16 ГБ уменьшите `finetune.batch_size`.

## Как устроено

1. **Предобработка:** чистка текстов, разбор параметров на вид/тип услуги и адрес. Адрес, цены и график вырезаются из текста.
2. **BM25** по всему корпусу. Оценка местных объявлений ×5, при совпадении вида услуги с фильтром x2.
3. **Эмбеддинги** e5-base, дообученной на парах «запрос -> выбранное объявление» из train. К сходству местных +0.3, при совпадении вида +0.2.
4. **RRF** с весами 0.4 (BM25) / 0.6 (эмбеддинги).

"Местные" — локации, куда уходит ≥ 1% выборов из локации поиска (по train), плюс радиус 50 км от её центра. Центр оценивается медианой координат выбранных оттуда объявлений: координат пользователя в данных нет. Все параметры — в `config.yaml`.

## Ход решения (валидация, recall@50)

| этап | |
|---|---|
| BM25 без нормализации слов | 0.341 |
| + лемматизация | 0.417 |
| + бонусы за локацию и вид услуги | 0.785 |
| + e5-base через RRF | 0.840 |
| e5-base -> дообученная | **0.887** |

## Ключевые решения

- **Валидация повторяет benchmark:** один запрос на текст, 37% текстов знакомы по train, 34% с фильтром вида услуги.
- **Локация — бонус, а не фильтр:** локации запроса и объявления совпадают лишь в 83% пар, жёсткий фильтр ограничил бы recall значением 0.77.
- **Корпус не фильтруется по категории:** у 9% benchmark-запросов категория 0 (поиск везде). Для запросов из «Услуг» не-услуги только ослабляются.
- **BM25 и эмбеддинги дополняют друг друга:** 7.4% ответов находит только BM25 (редкие слова, марки), 8.5% — только эмбеддинги (синонимы, опечатки).

## Ограничения и развитие

- Запросы с категорией 0 в валидации не представлены.
- 38.7% правильных объявлений валидации встречаются в обучении как ответы на другие запросы. `evaluate.py` показывает recall отдельно для группы без них — это осторожная оценка.
- Не подбирались: `k1`, `b`, `rrf_k`, штрафы не-услуг, параметры дообучения. Бонусы подбирались по одному, а не совместно.
- Дальше: hard negatives при дообучении, модель крупнее, ранжирующая модель над кандидатами.
